# System evidence collection

Run `python scripts/collect-system-evidence.py` from the workspace. Each call creates a new `artifacts/system-evidence-<UTC>-<id>/` with `evidence.json` and `summary.md`; it runs no EDA jobs or model APIs. Validate the collector with `python tests/test-system-evidence.py`.

The index covers SoC, DMA, UDP and AES. It reads all retained `system-<project>-<stage>-*` receipts and discovers XSim/Vivado artifacts through `inputs.json` and `invoked.tcl`, including failed attempts that never reached `latest-*.json`. It also reads `<project>-direct-*/result.json` independently of latest pointers, so direct attempts remain discoverable after those pointers change. Latest pointers and historical attempts remain separate. The newest retained tool artifact supplies each summary row; older failures remain in `runs`.

Ordering uses explicit recorded start timestamps first, then ISO timestamps in process logs, then ISO directory timestamps. When those are absent, it uses metadata-file modification time, preferring `command.json` over result files. Each run and summary row records `ordering_timestamp_utc`, `ordering_basis` and `ordering_source`. File modification time is only a fallback sorting observation; it is never reported as a run's start or end. Timezone-free strings and ambiguous labels such as `aes-direct-181959` are not interpreted as UTC dates.

Every captured file records its original absolute path, SHA-256, capture UTC, byte count, modification time and whether it changed while being read. JSON retains runner results, pass markers, case counters, errors, observed timeouts, build results, reported setup/hold slack, resources, timing checks and applied constraints. Large waveforms and checkpoints stay in their original directories and are not copied or hashed.

Both legacy `xsim`/`vivado` and traced `eda_xsim`/`eda_vivado` directories are supported. Existing `run.json` manifests and `events.jsonl` are indexed; original trace manifests and reported input drift are retained separately. `command.json` and `source-manifest.json` retain their original paths, collection hashes and parsed payloads. This collector does not revalidate source or snapshot hashes declared inside those manifests.

A simulation pass requires exactly one project pass marker, terminal evidence, a stable log, and no fatal/error/timeout or recorded failed exit/verdict. Implementation also requires routed completion, matching nonnegative setup and hold slack in JSON and timing report, utilization and applied constraints. A negative control requires its specific expected mismatch; compile failures and arbitrary nonzero exits do not establish rejection. Partial case markers are evidence of partial execution only.

`in_progress_or_interrupted` means terminal evidence is absent. It does not assert that a process is alive. Unlinked wrapper receipts are retained separately because matching runs by similar timestamps alone would invent provenance. Missing files and malformed JSON remain visible in `files`.

These are collection-time hashes. Existing logs and current source/fixture hashes do not prove that historical inputs were frozen before execution. Reproduction must verify recorded paths and current inputs; exact historical source bytes cannot be recovered from paths alone. This collector creates an index and extracted evidence, so original logs/reports must be retained alongside it. OOC timing does not establish board I/O timing or hardware operation. Collector model API calls are zero; Codex token usage is unknown.
