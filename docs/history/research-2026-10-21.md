# 本地模电 / Vivado Agent 调研

这是 2026-10-21 的历史选型记录。后续已按用户选择实现原版 Pi 的 native EDA Agent，当前启动方式和验证结果以根目录 README.md 为准。

核对日期：2026-10-21。当前阶段为源码查看与选型；未安装接入工具、未运行仿真。

建议先用现有 Codex 接 AMD Ross 与 LTspice 官方 MCP，减少需要维护的组件。社区中查到的完整工程分享以 Claude Code 搭配较多；这是本次样本的观察，没有可靠的实际用户量排名。Pi 适合后续需要自己控制工作流时采用。

## 本地取得的内容

- AMD 官方仓库已克隆至 `vendor/ross-ai-assistant`，HEAD 为 `2cdc9eef1b6b5b17fa45f5e4d468e5483a1c92de`，工作树干净。包含技能、文档、示例和辅助脚本；独立 MCP 服务程序另行分发。[官方仓库](https://github.com/Xilinx/ross-ai-assistant)
- Windows MCP 2026.9.1 的官方下载入口跳转至 AMD 账户退出/错误页，本次没有取得可执行文件。[官方下载页](https://www.amd.com/en/support/downloads/ross-agentic-ai.html)
- 本机已确认有 Vivado 2020.2 的 `vivado.bat` 与 `xsim.bat`。AMD FAQ 声明支持 2020.2 起，但测试基线是 2026.1；各技能另有最低版本要求，仍需实际验证本机兼容性。HLS 构建技能使用较新的 `v++` / `vitis-run`，不能据此推定兼容旧版 Vitis HLS。[FAQ](https://github.com/Xilinx/ross-ai-assistant/blob/2cdc9eef1b6b5b17fa45f5e4d468e5483a1c92de/docs/faq.md)
- 注册表卸载项和常见安装路径未发现 LTspice；未进行全盘搜索。官方更新信息显示 Windows 版 26.1.1；26.1.0 加入 MCP，26.1.1 改进 MCP。[官方更新记录](https://ltspice.analog.com/download/updates.txt)

推荐组合是：**现有 Codex + AMD Ross 技能 / MCP + LTspice 官方桥接**。AMD 明确列出 Codex CLI 等 MCP 客户端支持；本机接通前仍只是选型结论。[AMD FAQ](https://github.com/Xilinx/ross-ai-assistant/blob/2cdc9eef1b6b5b17fa45f5e4d468e5483a1c92de/docs/faq.md)

LTspice 官方桥接优先用于现有电路和仿真交互。需要更丰富的批处理时，再评估 Cognitohazard 项目；其文档区分官方服务名 `ltspice` 与社区服务名 `spice`，两者可以共存，但也增加维护面。[社区使用文档](https://github.com/Cognitohazard/ltspice-mcp/blob/main/docs/USAGE.md)

后续搭建的验收建议：Vivado 先完成一个小 RTL 的仿真、综合与时序报告；LTspice 先完成 RC 的 AC / 瞬态分析，并与手算截止频率比较。每次升级重跑这两个小项目，保存工具版本、输入、日志与结果。固定 testbench 和约束基线，单独审查对验收标准的修改。这些是建议的后续工作，本轮未执行。
