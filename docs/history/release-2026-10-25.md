# Framework release · 2026-10-25

本文保留 0.3.0 首次发布记录。0.4.0 的任务层改进、源码对照和剩余差距见 [仓库比较](repository-comparison-2026-10-25.md)，当前发布副本验收见 `release/validation.json`。两轮软件检查与历史 FPGA 成绩分别记录。

原生接口由 16 项扩展到 48 项：28 个细粒度入口固定 report/kind/action 等选择，另有 4 个历史成绩接口。CLI、Pi 与 MCP 共用参数校验，隐藏字段不能将只读 plan 变为 run。已有通用入口继续可用。

新增能力包括器件/IP/命令检索、8 类单独报告、5 类网表对象查询、setup/hold 路径、trace 检查/恢复检查/本地导出、run 查询/清理失效租约、benchmark 分阶段入口。实际执行仍使用共享调度器、trace 与 Vivado 后端。完整结构化合同由注册表生成：[工具目录](../reference/tools.md)。

11 组历史记录接入结果工具，保留原始文件哈希、公开脱敏副本哈希、单位、输入群体、测试协议和限制。原始 20/24 与延长 watchdog 的 23/24 不作同条件成绩比较；0 ns 优化收益保留。

已加入可生成本机路径的 MCP 配置、Python 后端安装脚本、固定版本 RTL 依赖获取、带备份的示例路径迁移、发布文件清单及 Windows 离线 CI。发布目录从允许清单生成，安装环境、会话、游戏目录、凭据和大体积 EDA 产物不进入仓库。

本机本轮离线验收：62 Node + 21 Python 检查通过，配置检查通过。后续发布副本独立验证见 `release/validation.json`（发布时生成）；历史 64 项验收记录继续保留原日期。全部软件检查使用假 EDA/本机子进程/MCP 控制面，其他模型 API 为 0、实际 EDA 新运行 0；外层 Codex token 未计量。

本轮新增专用接口完成参数路由、拒绝非法调用、MCP 协议及证据测试。各 Vivado 操作沿用已有执行器；未声称每个新工具名都已再次通过真实 Vivado 调用。当前 MCP 连接需重连以刷新工具列表。

发布副本在独立目录执行 npm/Python 安装后，83 项检查再次通过，benchmark 目录 77 项入口通过结构校验。Python 依赖锁定已验证版本；Pi 间接依赖 `undici` 覆盖至 8.12.2，npm 审计为 0 项已知漏洞。目录入口数量不等于本轮实际运行题数。

首次 GitHub Windows CI 因自动 LF→CRLF 转换触发两项证据哈希失败；保留失败运行。`.gitattributes` 现要求按提交字节检出，避免原始测试和证据在跨环境 checkout 时被改写。Pi 生成配置显式使用 codemode exposure，与本机原配置一致。
