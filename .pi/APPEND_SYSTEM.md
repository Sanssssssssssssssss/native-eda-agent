Use `eda_preflight` before planning a run, `eda_benchmark` for the catalog and fixed acceptance, `eda_knowledge` for scoped primary-source rules, `eda_trace` for evidence integrity, and `eda_runs` for job state. Disable wave capture unless a specific debug question requires it.

Use Chinese unless the user requests another language. This is a local Pi workspace for Vivado 2020.2 and LTspice 26.1.1. The model connection uses the existing DEEPSEEK_API_KEY environment variable. Never read, print, copy, or persist credentials.

Use the `eda_xsim` tool for RTL simulation, `eda_vivado` for an authored Tcl build script, and the official `ltspice` MCP tools for analog simulation. `eda_ltspice_batch` provides a batch alternative. These tools run real installed EDA executables. Inspect files and tool schemas before acting.

For digital FPGA work, prefer the typed native operations when they fit: `eda_vivado_catalog` queries installed parts/IP/commands; `eda_vivado_synthesize` takes explicit sources, top, part and XDC; `eda_vivado_implement` consumes its checkpoint; `eda_vivado_reports` diagnoses timing/CDC/DRC/methodology/clocks/exceptions/routing; `eda_vivado_objects` inspects the netlist; `eda_vivado_timing_paths` returns bounded setup/hold paths. Read `docs/fpga-native-tools-2026-10-24.md` for inputs and verification boundaries. All share the Vivado resource lease and keep fresh artifacts. These are this project's native adapters, not the official Ross server.

`eda_vivado_optimize` adds a provider-free candidate loop using the pinned RouteAgents pure feature router and AER-inspired plateau stopping. Default mode=plan measures a routed DCP; mode=run executes a bounded portfolio and rechecks the winner. It shares the Vivado resource lease and traces. Read docs/native-optimizer-2026-10-24.md; preserve timing constraints and inspect every rejection, actual gain, winner_recheck and input_unchanged. A matching exported logical representation is not formal or simulated equivalence. Seven local physical strategies are implemented; only Explore/AggressiveExplore rerouting has live validation so far. The full 42-play upstream catalog is knowledge/routeagents-playbook.json, with explicit local adaptation status. Never launch the vendored dcp_optimizer.py or provider clients under the current no-model-API setting.

`eda_xsim` accepts include_dirs, defines, generics, installed library names, plusargs, sv_seed, timeout_seconds and a literal pass_marker. Use separate calls for parameter/seed cases and preserve their arguments. It can compile explicit Verilog/SystemVerilog and VHDL sources. For IP-heavy simulation requiring generated models or custom compile libraries, inspect/export the actual Vivado project with the existing Tcl tool; the typed source list does not automatically generate or discover those libraries. Never substitute an empty marker or unknown metrics for acceptance. Setup/hold, constraint completeness, CDC, routing, functional behavior and board validation remain separate decisions.
